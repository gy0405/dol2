# 돌돌이 트래픽 플레이북 — 사이트를 어떻게 돌아다녀야 하나

돌돌이는 **Burp에 이미 쌓인 트래픽만** 본다. 즉 **네가 안 돌아다닌 기능은 평가 자체를 못 한다.** 그래서 "어떻게 browsing 하느냐"가 결과의 품질을 절반 이상 결정한다. 이 문서는 돌돌이가 볼 거리를 만들기 위한 browsing 가이드다.

> ⚠️ 반드시 **인가된 점검 대상**에만 수행한다. 아래는 공격이 아니라, 정상 기능을 "고루 사용"해서 분석할 트래픽을 남기는 절차다.

---

## 공통 원칙 5가지

1. **정적 페이지만 보지 말고 "기능"을 써라.** 로그인·검색·폼 제출·상태 변경·객체 조회처럼 **서버로 요청이 가는 동작**이 분석 재료다. 메인 화면만 보면 돌돌이가 볼 게 없다.
2. **인증 전/후를 둘 다 남겨라.** 로그인 전 상태와 로그인 후 상태 모두에서 같은 기능을 써보면, 접근제어 경계가 트래픽에 드러난다.
3. **계정 2개로 교차로 돌아다녀라.** 권한 우회(IDOR) 계열은 "A가 되고, B가 되고, 서로의 것을 건드려봐야" 보인다. (아래 IN 항목)
4. **입력창엔 특수문자를 한 번씩 넣어라.** `"`, `<`, `>`, `'` 가 든 값을 검색/폼에 넣어보면 반사형 XSS 표면이 트래픽에 남는다.
5. **상태 변경 동작(POST/PUT/DELETE)을 포함해라.** 글쓰기·설정 변경·구매·삭제 같은 걸 실제로 해봐야 CSRF·세션 계열이 평가된다.

---

## 가이드 항목별 "이렇게 돌아다녀라"

돌돌이가 지금 탐지하는 것과, 그걸 띄우려면 어떤 트래픽이 필요한지.

### [IN] 불충분한 권한 검증 (IDOR / 수평 권한) — 돌돌이의 핵심 강점
객체 id가 URL/파라미터에 드러나는 기능을 **두 계정으로** 사용한다.
1. **계정 A로 로그인** → 주문내역·장바구니·프로필·문서 조회처럼 `.../something/{id}` 형태가 생기는 기능을 사용. (예: `/rest/basket/1`, `/api/Users/1`)
2. **로그아웃 후 계정 B로 로그인** → 같은 기능을 사용. (예: `/rest/basket/2`)
3. (가능하면) A로 로그인한 상태에서 **B의 id를 직접 접근** 시도. (예: 주소창/요청의 id를 2↔1로 바꿔보기)
→ 같은 엔드포인트 템플릿(`/rest/basket/{id}`)을 **서로 다른 신원**이 접근한 트래픽이 쌓이면, 돌돌이가 `horizontal-authz`로 잡는다.

### [XS] 크로스사이트 스크립트 (반사형)
입력이 **서버 응답(HTML)에 되돌아오는** 지점을 찾아 특수문자를 넣는다.
1. 검색창·게시글 제목·이름/프로필 입력·URL 쿼리 파라미터에 `"><b>dol2` 같은 값 입력.
2. 그 값이 **그대로 화면/응답에 보이는** 페이지를 방문.
→ 응답이 HTML이고 특수문자가 인코딩 없이 반사되면 돌돌이가 잡는다.
※ 한계: 응답이 JSON이거나, 반사가 브라우저 DOM에서만 일어나는 SPA는 안 잡힌다(아래 "못 보는 것" 참고).

### [IS] 불충분한 세션 관리 / [SN] 데이터 평문 전송 / [CF] CSRF / [CC] 쿠키 변조
**세션 쿠키가 트래픽에 남게** 만들고, 상태 변경을 수행한다.
1. **로그인/로그아웃을 수행** → 서버가 `Set-Cookie`로 세션 쿠키를 내려주는 트래픽이 남는다. (JWT를 localStorage에 넣는 사이트는 세션 쿠키가 없어 이 계열이 조용할 수 있음 — 정상)
2. **상태 변경 동작을 POST/PUT/DELETE로 수행** (글쓰기, 설정 변경, 구매, 삭제).
3. (가능하면) **평문 HTTP 구간**도 한 번 거친다(http:// 접속). → HSTS/Secure 체인 평가.
→ 세션 쿠키 + 상태변경 + (평문) 조합이 있어야 쿠키/세션/CSRF/평문전송 체인이 성립한다.

## 돌돌이가 트래픽을 아무리 쌓아도 "못 보는 것" (정직하게)

browsing으로 해결 안 되는, 현재 설계의 범위 밖:
- **DOM 기반 XSS** — 반사가 브라우저 안에서만 일어나면 HTTP 응답엔 안 남는다(SPA의 전형). 서버 응답 분석으로는 안 보인다.
- **저장형(stored) XSS** — 한 요청의 입력이 *다른* 응답에 나타나는 추적은 아직 미구현.
- **수직 권한 상승 / 인증·인가 로직의 의미적 결함** 중 트래픽 패턴만으론 드러나지 않는 것.
- **서버/OS/DBMS/네트워크 설정 점검** — 가이드의 웹 외 장(章)들. 웹 트래픽으로 관찰 불가 → 돌돌이 범위 밖.

이들은 "돌돌이가 조용하다 ≠ 안전하다"에 해당한다. 돌돌이 결과는 **사람 점검을 대체하는 게 아니라 우선순위를 잡아주는 것**임을 항상 전제한다.
